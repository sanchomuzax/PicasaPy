#   * A lista HOSSZA sem nőhet: a felső korlát a szkriptben áll

#     azt pedig a felülvizsgálat látja. Ahogy a lista fogy, vidd lejjebb.
#   * Ha egy tétel bekötést kap, a sorát TÖRÖLNI kell: az őr az elavult
#     bejegyzésre is bukik, hogy a lista ne konzerválja a múltat.

# Indoklás nélküli sor HIBA — a néma engedély pontosan az, ami ide nem kell.

# -- Az effektus-vágólap MÁSODIK rétege (#152) — ELDŐLT: marad, felület nélkül
# A #1475 eldöntötte: a felület mögötti út a KÖTEGELT réteg
# (`photo_ops_controller`), annak mind a négy tagja bekötést kapott, ezért

#
# A #1534 VISSZAFEJTETTE az eredeti kezelőket. Két dolog derült ki:
#
# 1) NINCS külön menüpont, amit ez a réteg kiszolgálhatna: a teljes
#    parancstérképben (docs/specs/picasa-menu-parancsok.csv) pontosan KÉT
#    effektus-vágólap parancs van, mindkettő a SZERKESZTÉS menüben. Az
#    eredeti EGY parancsot ad, KÉTÁGÚ kezelővel (a szerkesztő nyitottsága
#    választ ágat) — nem két külön funkciót. Saját menüpontot adni: HIBA.
#
# 2) Az eredeti a láncot EGÉSZBEN viszi át — a másolás/beillesztés teljes
#    hívási útján NINCS szűrő-névre vonatkozó összehasonlítás, és a `crop64`
#    sztringnek NULLA kódhivatkozása van a binárisban. Vagyis a VÁGÁS
#    ÁTMEGY, és ennek a rétegnek a tartalmi szemantikája a HŰSÉGES — nem a
#    bekötött kötegelté, amely a filterdesc.xml mode="history" oszlopából
#    KÖVETKEZTETVE szűr, holott a kezelő ezt az attribútumot nem olvassa.
#
# Ezért NEM töröljük: ma ez a helyes viselkedés egyetlen megvalósítása. A
# kötegelt réteg szűrésének javítása külön jegy dolga.
# ⚠️ A többszintű undo-verme viszont az eredetiben NEM létezik (a
# könyvtárnézeti beillesztés ott visszavonhatatlan) — azt nem kell átvinni.
